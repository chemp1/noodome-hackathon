# Вайб-кодинг-хакатон Noodome · 5 сентября · 3 часа

Материалы хакатона команды Noodome: 12 треков — у каждого автора идеи свой.
В каждом треке пресет: бриф с цепочкой промптов на 105 минут, синтетические
данные и три уровня амбиции. Скоуп изобретён заранее — команды тратят время
только на работу, а не на придумывание, что делать.

## Три уровня в каждом треке

- **🎯 Прототип** — гарантированный живой путь, его доводят все.
- **⚡ Инструмент** — то, ради чего задача затевалась (воронка заявок, деньги под
  риском, контроль SLA). Переходить, только когда Прототип живой.
- **🚀 Продукт** — для тех, кто летит: то, что не стыдно показать наружу.

Правило дня: работающий Прототип бьёт сломанный Продукт.

## Цепочка промптов вместо одного запроса

Главное отличие от «попросил — получил»: в каждом брифе цепочка из 8 шагов,
где каждый следующий опирается на собранное. Начинается она **не с кода**, а с
исследования — команда изучает, как эту задачу решают лучшие в мире, и собирает
**артефакт-разбор референсов**. Дальше: разведка данных → каркас → проверка
руками → углубление → критика от лица пользователя → амбициозный шаг →
полировка. На демо показываются оба артефакта: что изучили и что построили.

## Программа

| Время | Что происходит |
|-------|----------------|
| за 1–2 дня | Сетап 1:1 по 15 минут: входы работают, брифы открыты, каркас бота задеплоен; опрос-бейзлайн разослан |
| 10:00–10:15 | Вводная: контекст и честные кейсы · живой пример вайб-кодинга (не из наших треков) · правила дня |
| 10:15 | Старт практики — 105 минут. Первые 20 минут растерянности это норма |
| 11:15 | Обход-чекпоинт: три вопроса самопроверки из брифов |
| 11:50 | Заморозка скоупа: только полировка одного живого пути |
| 12:00 | Стоп-кодинг, бэкап-записи экрана (2 минуты на команду) |
| 12:05–12:25 | Блиц-демо: 12 команд × 90 секунд — только живой путь, показывает автор боли |
| 12:25–12:45 | Ярмарка: все ходят по столам, трогают чужие прототипы, голосуют |
| 12:45–13:00 | Номинации · владелец и дата пилота у каждого прототипа · план после |

Тайминг внутри брифов (0:00–1:45) отсчитывается от старта практики.

## Три правила участника (на каждом столе)

1. **Начни с разведки:** «покажи, что в этих файлах».
2. **Проси конкретный результат:** «сделай экран с тремя карточками и поиском», а не «сделай красиво».
3. **Проверяй след данных:** возьми строку из исходника и найди её в результате.

Застряли — спасательный промпт: «Задай мне вопросы, чтобы лучше понять, каким должен быть этот продукт».

⚠️ **Правило данных:** весь хакатон работаем только на синтетике из этих папок.
Реальные данные участников клуба и переписки в облачные ИИ не загружаем.
В синтетике намеренно спрятаны ошибки — как в жизни; кто найдёт, говорит на демо.

## Судейство

Пять критериев по 0–3 балла (максимум 15), публикуются до начала:

| Критерий | Вопрос судьи |
|----------|--------------|
| Работает вживую | Один реальный путь показан в действии, не на скриншотах |
| Боль снята | Автор боли подтверждает: «это решает мою проблему» |
| Путь к внедрению | Понятно, что нужно, чтобы пользоваться через 30 дней |
| Честность ИИ | Показан промпт; проверяли руками; поймали ли выдумку или ошибку в данных |
| Понятность демо | Коллега из любого отдела понял без пояснений |

Достигнутый уровень (⚡ Инструмент / 🚀 Продукт) и качество разбора референсов
поднимают баллы в «Боль снята» и «Путь к внедрению» — но только если показаны вживую.

Плюс номинации вне рейтинга: «Скорее всего будут пользоваться» ·
«Больше всех экономит времени» · «Лучшая провокация ИИ» · «Лучший разбор
референсов» · «Народный прототип» (голосование, приз — выходной) · «Открытие дня».

## После хакатона (48 часов)

- Ссылки на все прототипы и артефакты-разборы — в общий чат в тот же вечер.
- У каждого прототипа — владелец (автор боли) и дата первого использования в работе (≤ 30 дней).
- Промпты и находки — в трек K, в библиотеку промптов клуба.
- Через неделю — повтор опроса «пользуешься ли ИИ ежедневно?».
- Следующая итерация — через квартал; цель-мечта — вайб-кодинг-вечер для участников клуба в амфитеатре.
